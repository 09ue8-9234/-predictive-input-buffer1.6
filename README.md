# Testing (v2.88.4)

This mod runs in the background and has no settings, menus or buttons inside Geometry Dash or Geode. It draws nothing and plays nothing unless you switch that output on (config.json or the external console).

- All settings are in `config.json` in the mod's save folder; a live console window opens with the game.
- External console: named pipe `\\.\pipe\abhyu-input-buffer-testing` (see `tools/pipe-test.ps1`).
- Keys work only while Geometry Dash is the active window. Defaults: F6 / Shift+F6 stage next / back, F7 low latency, Shift+F7 performance mode, F8 export, Shift+F8 run check, F9 training mode, Shift+F9 wave auto-release, F10 path view, F11 forget level, F12 stats, Ctrl+F1/F2/F3 presets Safe / Balanced / Aggressive.
- Custom slots A-D (stages 7-10, up to 128 ticks, nameable): Alt+1..4 jump to a slot, Ctrl+F12 / Ctrl+F11 add / remove 1 frame live. Every key can be changed in config.json (`bind.<action>`).
- In-game output toggles (all off by default): Shift+F11 death heatmap, Shift+F12 save ding, Ctrl+F6 hint text, Ctrl+F7 AUTO INPUTS tag, Ctrl+F8 TPS text, Ctrl+F9 watermark, Ctrl+F10 level complete label.
- The stage key (F6) cycles 0.25f (1 tick) -> 0.5f -> 1f -> 2f -> 4f -> 6f -> 8f -> custom A, B, C, D -> off; Shift+F6 goes back. 1 tick = 0.25f at 240 steps/s. A fresh install starts on 0.5f. Presets: Safe = 2f, Balanced = 4f with 2f wave, Aggressive = 8f. The stage in an older config.json keeps its meaning when the file is upgraded.
- At 0.25f the window is a single tick: only a 1-tick delay is tried, so the wave safety margin, the robust fallback delays and learned delays above 1 tick can't apply, and orb alignment only sees about 3 ticks ahead.
- Keys only work while the game window itself is in front (not the live console window).
- Run check (Shift+F8) replays your best recorded run in one go at the start of the next attempt; a very long recording (up to 200,000 steps) can freeze the game for a moment while it runs. It compares P1 only and does not replay triggers or moving objects.
- Fix toggles (config.json, each also has an unbound `bind.toggle:` key): `fix-restart-state` is on by default; `fix-dual-harmless`, `fix-lowlat-queue`, `fix-group-on`, `fix-orb-checks`, `fix-more-time-checks`, `fix-training-auto`, `fix-mover-conflict` and `fix-auto-throttle` are off by default. See the setting descriptions (get_config / schema) for what each changes.
- If config.json can't be read it is kept as `config.corrupt.json` before defaults (or the last good copy) are used. A save that fails is retried and noted once in the console. A full console command queue now answers with an error and counts the dropped commands (`droppedCmds` in the state message).
- v2.88.0 (ported from BASU's v2.84, each has its own setting): `unlimited-delay` (off, Ctrl+F4) removes the stage's cap on how early an input may be (limited by the prediction time budget); `ship-uses-stage` (on) lets the ship use the stage's delay, never less than its own; `orb-press-passthrough` (on) lets a press that touches an orb go through unchanged and stops orb timing from re-timing it; `orb-same-target` (on) only counts timings that use the first orb ahead; `inverted-wave` (on) uses quicker-turn rules for an upside-down wave. A delay of up to unlimited can hold an input a long time if that is the first timing that survives; turn the setting off if that feels wrong.
- The decision rules of v2.88 are in `src/prediction_policy.hpp` and tested by `tests/prediction_policy_test.cpp`; the config loading is tested by `tests/cfg_test.cpp`. The "Build Testing App" workflow runs both before building the app; locally: `g++ -std=c++17 tests/cfg_test.cpp -o t && ./t`.
- Console link and window (v2.88.3): `console-link` (on) opens / closes the named pipe, Ctrl+F5 switches it; `console-window` (on) shows / hides the live console window, Shift+F5 switches it. Both are on by default, which is how it always was. The mod also writes `schema.json` (every setting, limits, stages, presets) next to `config.json` at load.
- v2.88.4: the practice-mode rule is gone. The buffer, auto-release (wave / robot / dash) and auto-click work in every run; the settings `practice-only`, `auto-release-normal-runs` and `fix-practice-queue` were removed (old keys in config.json are ignored and dropped at the next save). The AUTO INPUTS tag only shows when its switch (Ctrl+F7) is on, and the state message no longer carries practice / TPS warnings. Key bindings in config.json are checked together after loading, so a swap (e.g. stage F8 / export F6) is kept; real clashes are resolved in table order and reported in the console (`config: key conflicts ...`). `tests/cfg_test.cpp` tests the config loading.
- **Testing app** (`app/`, version 1.0.1): a Windows desktop app that edits every setting. Game closed: it edits `config.json` directly (backup first, atomic save). Game running: file editing is locked; press "Connect to game" to change things live over the pipe (one client at a time, so `tools/pipe-test.ps1` and the app can't be connected together). See `app/README.md`. The GitHub build produces `Testing.exe` as the artifact "Testing App".
